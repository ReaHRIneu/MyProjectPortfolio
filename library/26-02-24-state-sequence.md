# 게임 디자인 기초 | 상태(State)·시퀀스(Sequence)

게임 속 객체의 행동을 설계하는 두 가지 핵심 도구를 학습하자

- 상태 : 현재 주어진(겪는) 상황
- 시퀀스 : 순서와 흐름
- IDLE 상태 → 패트롤 상태(이동) → 반경 내 존재(유저/엔티티) 여부 확인 [비전투상태] → 추적 상태 → 공격 상태 → 추적 조건 확인(타이머/범위)[전투상태] → 복귀 or 상태 유지

## "어떤 상태가 필요한가?"

게임 속 모든 객체는 **상태**를 가진다. 캐릭터가 걷고, 뛰고, 공격하고, 죽는 모든 순간이 하나의 상태이다. 이 강의에서는 상태를 체계적으로 정의하고 관리하는 방법을 알아보자.

## 상태가 왜 필요한가?

### "클래스 다이어그램만으로 구조를 명확히 정의할 수 있을까?

- **고블린 예시**: 고블린은 이동, 근접공격, 도망 등 다양한 행동을 한다. 클래스에 ID, HP, 공격력 같은 데이터를 담을 순 있지만, **언제 어떤 행동을 하는지**는 설명할 수 없다.

> 저렙 유저용 기본 몬스터. 한 번에 3~5마리씩 떼를 지어 생성된다. **행동 규칙**은 *상태 다이어그램*으로 정의해야 한다.

## 대전 격투 게임의 복잡한 상태

대전 격투에서 캐릭터는 **상황과 상태에 따라** 애니메이션, 판정 범위, 데미지 등 수많은 요소가 변한다. 단순한 클래스 정의만으로는 이런 **동적 규칙**을 설명할 수 없기 때문에, *상태 다이어그램*이 필수이다.

## 상태 다이어그램

### 상태 다이어그램

- 시간의 흐름에 따라 객체에 발생하는 변화를 모델링하는 수단
- 단일 객체를 대상으로 상태 변화를 추적
- 게임 캐릭터, UI, 시스템 등 다양한 곳에 활용 가능

### **핵심 구성 요소**

- **상태**: 객체가 머무는 조건
- **전이 (Transition)**: 상태 변화 및 조건
- **하위 상태**: 상태 내부의 세부 단계

### 상태 다이어그램의 기본 구조

1. **상태 이름**: 예 : "사망 상태" - 객체가 현재 어떤 상황에 있는지 식별
2. **상태 변수**: 상태 진행에 필요한 데이터. 예 : HP=0, moneyLoss=UserLv*100, ExpLoss=CurrentExp*0.1
3. **활동 (Activity)**: 사건(Event)과 동작(Action)으로 구성

*(이미지 생략: 상태 다이어그램 기본 구조 예시)*

- **Entry**: 상태 진입 시 수행. 예 : HP가 0 이하가 됨
- **Do**: 상태 유지 중 수행. 예 : 화면 흑백, 금액·경험치 감소
- **Exit**: 상태 탈출 시 수행. 예 : 부활 방법 선택

### 상태의 전이

상태는 **조건**이 충족되면 다른 상태로 전이된다. 라면의 상태 변화로 이해하자.

*(이미지 생략: 상태 전이 예시 - 라면 조리 과정)*

1. **상태 흐름의 시작**
2. **상태의 종료**
3. **상태의 전이**
4. **상태 진입 포인트**
5. **상태 탈출 포인트**

### 하위 상태 (Sub-state)

하나의 상태 안에 더 세밀한 **하위 상태**가 존재할 수 있다. 라면의 "조리 상태"를 예로 보자.

*(이미지 생략: 하위 상태 예시 - 라면 조리 상태)*

## 상태 변화와 비주얼 피드백

게임에서 상태가 바뀔 때는 대체로 **애니메이션이 전환**되거나 **이펙트가 추가**된다. Idle → Run → Attack 각 전이마다 시각·청각적 피드백이 플레이어에게 현재 상태를 알려준다.

- '상태'와 '상태 이상'의 차이 - 각각 개별(독립)적인 요소

## 시퀀스 다이어그램이란?

### 핵심 개념

시간에 따라 순서대로 발생하는 사건을 표시하는 다이어그램이다. 여러 객체가 서로 어떤 메시지를 주고 받는지 시각화한다.

> **상태 다이어그램**은 단일 객체의 내부 변화를 기록하고
> **시퀀스 다이어그램**은 여러 객체 간의 사건 흐름을 기록한다.

### 구성 요소

- **객체**: 상호 작용 참여자
- **메시지**: 객체 간 전달 내용
- **시간**: 위 → 아래 시간 흐름

### 시퀀스 다이어그램의 기본 구조

"학생"과 "학교" 두 객체 사이의 등교·하교 메시지로 가장 단순한 시퀀스를 살펴보자

1. **객체 (Object)**: 상호작용에 참여하는 *주체*
2. **생명선 (Lifetime)**: 객체의 존재 기간을 표시하는 *점선*
3. **실행 (Activation)**: 객체가 활성 상태인 *구간*
4. **메시지 (Message)**: 객체 간 전달되는 *요청이나 응답*

*(이미지 생략: 시퀀스 다이어그램 기본 구조 예시)*

### 메시지의 종류

- **단순 메시지**: 일반적인 메시지 전달(*실선 화살표*)
- **동기(호출) 메시지**: 응답을 기다리는 메시지(*채워진 화살표*)
- **답신 메시지**: 호출에 대한 반환(*점선 화살표*)

*(이미지 생략: 메시지 종류 예시 다이어그램)*

### 분기, 상태 추가, 객체 생성

스타크래프트의 해병 생산 과정을 시퀀스 다이어그램으로 표현한 예시이다.

- **분기 조건**: [광물≥가격]or[광물<가격]
- **상태 표시**: 대기, 생산중 등 객체 상태
- **객체 생성**: 생산 완료 시 해병 객체 생성

*(이미지 생략: 해병 생산 시퀀스 다이어그램)*

## 시퀀스 다이어그램의 활용 포인트

시퀀스 다이어그램은 페이지나 씬이 전환되는 흐름이 아니라, **동일한 페이지·씬 안에서** 객체 간의 사건 진행을 표시하는 데 가장 효과적이다. 전투 한 판, UI 인터랙션 한 사이클 등을 정리할 때 활용하자.
