# 게임 디자인 기초 | 객체 지향 설계

객체 지향 설계의 핵심 원리를 게임 디자인의 관점에서 배워봅시다.

## 객체 지향 기본 개념

게임 세계를 구성하는 모든 것의 출발점

- 객체 : 사물(물체) → 실체하는 것 + 실체하지 않는 것 → 명사
  최소 단위 - 오브젝트(객체)
- 절차적 설계 방법 : 순서대로 동작하는대로 설계

→ 사물 중심 코딩(개발)

## 객체(오브젝트)

### 객체는 주변을 이루고 있는 모든 것

붕어빵, 신발, 건물, 머리카락… 우리 주변의 모든 사물이 곧 객체이다

### 객체의 구조 = 속성 + 행동

- 속성(구성요소) : 이름, 가격, 칼로리, 속재료
- 행동(동작) : 익혀진다, 먹힌다, 잘린다

> 속성과 행동을 추가할수록 모델은 실세계에 가까워진다.

→ 객체를 추상적으로 구현한다

## 클래스

RPG의 법사, 전사 같은 클래스가 아니다. **객체를 추상화한 설계도**를 클래스라고 한다.

- **클래스 = 보편자**: 플라톤의 이데아처럼 개념 자체를 정의
- **객체 = 실현자**: 실제 세상에 존재하는 구체적 인스턴스

예) 인간(클래스) → 양현석, 김태희, 레이디가가, 빌리(객체)

## 객체 지향의 주요 개념

객체 지향 설계를 지탱하는 6가지 핵심 원리를 하나씩 살펴보자

- **추상화**: 필요한 속성과 행동만 정의
- **상속**: 상위 클래스의 특성을 물려받음
- **다형성**: 같은 메시지, 다른 응답
- **캡슐화**: 내부 구현을 외부에 숨김
- **메시지 전송**: 객체 간 소통 방식
- **연관**: 객체 사이의 관계 설정

### 추상화

**필요로 하는 만큼의 속성과 행동만 정의하는 것**이 추상화이다. 게임 세계를 기획한다는 것은 곧 속성과 행동을 정의하는 일이며, 어떤 게임이냐에 따라 그 범위가 달라진다.

**예) MMORPG 몬스터**
HP, 드롭 아이템, 공격력, 움직인다, 죽는다

**불필요한 정의**
나이, 취미, 학력, 삐진다, 공부한다

> 적당한 추상화는 콘텐츠 구현의 자유도를 높이고 최적화를 돕는다. 시스템 디자인의 가장 중요한 요소 중 하나이다.

> 모든 속성과 행동을 정의할 필요는 없다. 그래서 추상화라고 한다.

### 상속

하위 클래스는 상위 클래스의 **속성과 행동을 물려받는다**. 무기 상속 관계를 통해 이해하자

*(이미지 생략: 무기 클래스 상속 관계도)*

단검과 철퇴 모두 상위 클래스의 **데미지라는 속성**과 **공격한다는 행동**을 물려받지만, **벤다**는 검 계열만 상속받는다.

### 다형성(Polymorphism)

같은 행동이라도 클래스마다 수행 방식이 다를 수 있다. 동일한 메시지에 서로 다른 방법으로 응답하는 기능이다.

- 칼 - 칼을 꺼내어 찌른다
- 철퇴 - 철퇴를 휘둘러 내리친다
- 총 - 겨냥 후 방아쇠를 당긴다 → 그런데 총알이 없다면?

> 3가지 무기는 모두 공격한다라는 명령으로 작동한다.

- Overloading 방식

### 캡슐화 | 정보 은폐

객체는 **자신의 오퍼레이션이 어떻게 작동하는지**만 알고 있으며, 외부에서는 알 수 없다.

- 은행 업무 시 은행원의 개인사를 알 필요는 없다
- TV를 켤 때 리모콘 동작 원리를 몰라도 된다

> 하나의 객체에 오류가 생겨도 다른 객체를 수정할 필요가 없다. 유지보수의 핵심 원리이자 캡슐화가 중요한 이유이다.

- 은폐 - 속성 → 보안 이슈

### 메시지 전송

객체 간에는 서로 메시지를 전송하여 상호작용한다.

리모콘 - 메시지를 보낸다
TV - 메시지를 받아 동작한다

### 연관

한 객체는 다른 객체와 관계를 맺을 수 있으며, **속성의 연관과 행동의 연관** 두 가지로 구분된다.

- **복수의 연관**: 객체는 다른 객체와 두 개 이상의 연관을 가질 수 있다.
- **다대상 연관**: 객체는 하나 이상의 다른 객체와 연관을 지을 수 있다.

### 연관의 종류

1. 다중성 연관: 선생-수업=1:1, 선생-학생=1:다 연관으로 관계의 수량을 표현한다.
2. 집합 연관: 한 객체가 여러 객체로 구성된다. 예) 농구팀은 농구선수들로 구성, 상속과 혼동하기 쉬운 개념이다.
3. 복합 연관: 구성 요소가 복합체 안에서만 존재하는 강력한 관계이다. 예) 프로농구팀은 반드시 프로리그에 포함되지만, 선수는 팀 소속이 필수는 아니다.

> 객체는 다른 객체와 연관을 맺기도 하지만 컴포넌트(부품)로써 존재할 수 있다.

### 속성

- **변수형 지정**: 속성:변수형 형태로 타입을 지정해 줄 수 있다.
- **초기값 설정**: 변수형=값 형태로 기본값을 지정할 수 있다
- **제약과 결합**: 제약 설정과 함께 속성이 가질 수 있는 값의 범위를 결정한다
- **변수형 종류**: 정수(int), 실수(float), Boolean(T/F), 텍스트(string) 등

### 행동/스테레오 타입/책임

- 행동: 행동(파라미터) : 반환값 구조로 정의한다
- 스테레오 타입: <<타입명>>으로 표시하여 속성과 오퍼레이션을 구분한다
- 책임: 클래스가 해야 하는 일을 지정하여 목적성을 정의하고 설계 방향을 잡는다.

### 제약/노트

- 제약 (Constraint): 속성 옆 중괄호 []로 값의 범위나 가능한 목록을 제한한다. 예) 아이스크림을 g 단위로 팔 것인가, 싱글/더블/패밀리 등 단계로만 제약할 것인가
- 노트 (Note): 속성:오퍼레이션 옆에 점선 연결된 포스트잇 형태로 표시한다
