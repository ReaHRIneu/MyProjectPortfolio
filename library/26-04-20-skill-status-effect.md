# "스킬 없이 게임을 하면?"

스킬은 단순한 기능이 아니다. 전투의 리듬, 플레이어의 표현, 게임의 깊이 그 자체이다.

# 스킬

스킬이란 플레이어가 캐릭터를 통해 발동하는 능동적 행위로, 전투·탐험·상호작용 전반에 걸쳐 게임플레이의 깊이와 다양성을 만들어내는 핵심요소이다.

#### 구성 요소

- 애니메이션 - 스킬 발동 시 재생되는 캐릭터 모션. 타이밍과 연출이 몰입감에 직결된다.
- 비주얼 이펙트(VFX) - 발동 순간 화면에 표현되는 시각적 연출. 스킬의 성격과 강도를 직관적으로 전달한다.
- 사운드 - 타격감과 몰입감을 높이는 음향 효과. 시각 연출과 함께 스킬의 '느낌'을 완성한다.
- 데이터 - 데미지, 쿨타임, 마나 소모, 사거리 등 스킬의 동작을 정의하는 수치 정보

#### 사용 방식

- 액티브 (Active) - 플레이어가 직접 키 입력을 통해 발동. 전략적 판단과 조작 실력이 요구된다.
- 패시브 (Passive) - 습득 후 특정 조건이 충족되면 자동으로 발동. 캐릭터의 기본 성능을 강화하는 역할을 한다.

# 게임 디자인에서의 중요성

버튼 하나를 누르는 순간, 플레이어는 세계에 개입한다. 스킬은 그 개입의 언어 - 얼마나 강력하고, 얼마나 다채롭게 설계하느냐가 게임의 기억을 결정한다

#### 전투의 재미

스킬의 타이밍, 조합, 연출이 전투에 리듬을 부여한다. 단순한 공격이 아닌, 판단과 실력이 빛나는 순간을 만들어낸다.

#### 캐릭터 개성

같은 게임이라도 어떤 스킬을 쓰느냐에 따라 플레이 스타일이 달라진다. 스킬은 캐릭터의 정체성을 가장 직접적으로 드러내는 요소이다.

#### 성장 체감

새로운 스킬을 습득하는 순간, 플레이어는 성장을 눈으로 확인한다. 스킬 트리는 단순한 수치 상승이 아닌, 가능성의 확장이다.

# 스킬의 구분

#### 발동 타입

- 인스턴트(Instant) - 입력 즉시 효과 발동. 반응 속도가 핵심. 일반적인 발동 형태
- 캐스팅(Casting) - 일정 시간 경과 후 발동. 선딜레이 동안 취약점 발생. 보통 캐스팅 바가 표시
- 차징 (Charging) - 충전 시간에 따라 위력이 달라지는 발동 방식. 누르고 있는 시간이 길어질수록 위력이 상승
- 채널링(Channeling) - 유지하는 동안 지속적으로 효과 발동. 중단 시 효과 소멸. 이동이나 공격을 맞으면 중단

#### 타겟 & 범위

- 타겟팅 - 특정 대상을 클릭하거나 선택하여 발동. 명중이 보장되므로 안정적이지만, 대상이 없으면 사용 불가. 단일 대상 스킬에 주로 사용.
- 논 타겟팅 - 방향 또는 위치를 기준으로 발동. 대상 없이도 사용 가능하지만 빗나갈 수 있음. 조준 실력이 결과를 좌우하며, 회피 가능성이 있어 전략적 깊이를 더함.
- 광역(AoE, Area of Effect) - 지정된 범위 내 모든 대상에게 동시 적용. 원형·부채꼴·직선 등 다양한 형태로 구현되며, 다수전에서 강력한 효과를 발휘. 아군 피해 여부도 설계 시 반드시 고려해야 함.

#### 역할

- 공격 - 적에게 직접 피해를 가하는 가장 기본적인 역할. 단일 타격, 연속 타격, 도트(Dot) 피해 등 다양한 형태로 구현되며, 데미지 계산 방식(물리/마법/고정)도 함께 정의해야 함.
- 버프 / 디버프 - 아군의 능력치를 일시적으로 강화(버프)하거나 적의 능력치를 약화(디버프)시키는 스킬. 지속 시간, 중복 적용 여부, 해제 조건 등 별도 설계 필요. 전투 밸런스에 직접적인 영향.
- 회복 - Hp·마나·스테미나 등 소모된 자원을 되돌리는 스킬. 즉시 회복과 지속 회복(HoT) 방식으로 나뉘며, 전투 지속력과 파티 생존율에 직결됨.
- 소환 - 독립적으로 행동하는 개체(소환수·함정·오브젝트 등)를 생성해 전투력을 증폭시키는 스킬. 소환물의 AI, 어그로 처리, 지속 시간, 최대 소환 수 등 별도 구조설계가 반드시 필요함.

# 스킬 설계 시 체크사항

#### 역할과 구조의 명확한 구분

상위 / 하위 클래스로 나누어 데이터량을 절약할 수 있는지, 혹은 복잡한 기능을 위해 데이터 사이즈를 늘려야 하는지 판단이 필요하다

예시 : "타겟팅한 적 1인에게 즉시 데미지 + 1초 간 주변 1m 내 적에게 스턴 + 독 데미지" - 이처럼 복합 효과는 클래스 분리를 요구한다.

#### 플레이 환경 고려

특히 멀티플레잉 환경에서 특정 스킬이 지나치게 강하거나 쓸모없어지는 상황을 사전에 방지해야 한다.

예시 : "적 HP 5%를 무조건 감소"하는 스킬을 20명 공대원 모두가 들고 레이드에 간다면? 벨런스 붕괴를 초래한다.

> 멀티 플레이어 환경에서는 다수의 사용자들이 동일한 스킬을 동시에 사용할 경우를 항상 고려해야 한다.

# 투사체 설계

*스킬과 투사체는 반드시 역할을 분리해 설계*해야 한다. 투사체를 별도 클래스로 독립시키면 유지보수성과 확장성이 크게 향상된다.

스킬 클래스는 *투사체의 생성*만 담당한다. 이동·폭발 등 실제 동작 로직은 별도 클래스와 스크립트로 분리해야 재사용성이 높아지고 디버깅이 수월해진다.

스킬 클래스는 *투사체의 ID·개수·생성 타이밍*만 제어한다. 크기·이동 거리·궤적·폭발 범위 등 세부 동작은 투사체 전용 테이블과 스크립트에서 투사체가 독립적으로 작동하도록 설계한다. 이 구조를 따르면 동일한 동작 방식의 투사체를 중복 제작할 필요가 없어지고, 새로운 스킬 추가 시 기존 투사체를 그대로 재활용할 수 있다.

# 소환물 설계

#### 투사체 설계와 유사한 프로세스

소환물 설계도 투사체와 동일한 분리 원칙을 따른다. 스킬 클래스는 어떤 소환물을 (ID), 몇 개를(개수), 언제 생성할지(타이밍)만 결정한다. 소환물이 실제로 어떻게 이동하고, 어떤 대상을 공격하며, 어떤 조건에서 사라지는지는 소환물 전용 클래스와 스크립트에서 독립적으로 처리한다. 이 구조 덕분에 동일한 소환물을 여러 스킬에서 재사용할 수 있고, 소환물의 동작을 수정할 때 스킬 클래스를 건드릴 필요가 없어진다.

#### 어그로 규칙 설정 필수

소환물의 어그로 처리는 설계 초기에 반드시 명확히 정의해야 한다.

1. 독립적으로 어그로를 끄는 방식. 적이 소환물을 별도 대상으로 인식하고 공격한다.
2. 주인의 어그로 수치에 합산되는 방식. 소환물이 가한 피해가 주인의 위협도로 계산된다.
3. 어그로를 전혀 생성하지 않는 방식. 순수 보조 역할에 적합하다.

#### AI 구조 설계

소환물은 플레이어가 직접 조작하지 않는 만큼, 몬스터와 동일한 수준의 AI 구조 설계가 필요하다.

이동 방식 - 주인을 따라다니는가, 제자리를 지키는가, 적을 추적하는가
공격 판정 - 사거리·공격 속도·피해량은 어떻게 계산되는가. 몬스터 테이블과 구조를 공유할 수 있는가.
타겟 선정 로직 - 가장 가까운 적을 공격하는가, 주인이 공격 중인 대상을 우선하는가, 별도 우선순위 규칙이 있는가.
소멸 조건 - 지속 시간 만료, HP 소진, 주인 사망 등 소환물이 사라지는 조건을 명확히 정의해야 한다.

이 구조를 몬스터 AI와 최대한 공유하면 개발 비용을 크게 줄일 수 있다.

# "상태 이상 설계"

Stun, Blind, Sleep, Silence… 복수의 상태 이상이 동시에 적용될 때 어떻게 처리할 것인가? 설계의 핵심 과제이다.

# 상태 이상 시나리오

#### 시나리오 1 | 복수의 상태 이상 동시 적용

내 캐릭터가 Blind 2초, Stun 1초, Silence 1.5초를 동시에 맞았다. 2초 동안 캐릭터는 어떤 상태가 되어야 할까? 각 시점별로 설명해라.

- Stun 효과 1초 → (1.0초 경과) Silence 효과 0.5초 → (0.5초 경과) Blind 효과 0.5초 → (0.5초 경과) 상태 이상 해제

#### 시나리오 2 | 상태 이상 위에 상태 이상

내 캐릭터가 Sleep 10초에 걸려있다. 이 상태에서 누군가 Stun 1초를 추가로 건다. 1초 후 캐릭터의 상태는 어떻게 되어야 할까? 우선순위와 처리 방식을 설명해라.

- Sleep 효과 지속 → Stun 효과 적용 → (1.0초 경과) 상태 이상 효과 해제

# 상태 이상 설계 시 체크사항

#### 모든 상태 이상 종류 정리

Stun·Blind·Silence·Sleep·Curse·KnockBack 등 게임 내 모든 상태 이상을 별도 테이블로 관리한다. 각 항목은 고유 ID, 효과, 지속 시간, 해제 조건을 포함하며, 추후 추가되는 상태 이상도 동일한 구조로 등록해 일관성을 유지한다.

#### 복수 상태 이상의 동시 적용 설계

단일 값이 아닌 리스트 구조(상태 이상 ID + 남은 시간)로 테이블을 설계한다. 매 틱마다 시간이 차감되고, 0이 되면 해당 항목이 자동 제거된다. 이 구조로 복수 상태 이상의 동시 적용·해제를 일관되게 처리할 수 있다.

#### 중복 처리 규칙 결정

같은 상태 이상이 중복될 때 세 가지 방식 중 하나를 상태 이상별로 정의한다.

시간 갱신 (Refresh) - 남은 시간을 덮어씀. Stun 등 강한 제어기에 적합.
누적 (Stack) - 시간 합산 또는 효과 강도 증가. 누적 횟수 상한 필요.
무시 (Ignore) - 중복 적용 차단. Sleep 등 피격 해제형에 적합.

#### 지속 시간 및 해제 방법 정의

지속 시간은 스킬 테이블에서 관리한다. (같은 Stun도 스킬마다 다를 수 있음). 해제 조건은 상태 이상별로 명시하며, 주요 유형은 다음과 같다. 시간 경과 / 피격(Sleep 등) / 해제 마법·아이템 / 특정 행동 / 사망 시 초기화 여부. 해제 조건이 복수인 경우 둘 중 하나만 만족해도 되는지 둘 다 만족해야 하는지 (OR·AND)에 대한 처리 방식도 함께 정의해야 한다.

# 버프(Buff)와 디버프(Debuff)

긍정적 효과와 부정적 효과가 동시에 작용할 때, 시스템은 어떤 우선순위로 처리해야 할까

# 버프 중복 시나리오

내 캐릭터가 **공격 속도 +10% 물약**을 마셨다. 이후 동료가 **공격 속도 +20% 버프**를 걸어주었고, 다른 동료는 **공격 속도 +5% 오라를** 상시 발산하고 있다.

#### 세 버프가 모두 독립 적용된다면?

최종 공격 속도는 기본 값이 몇%가 되어야 하는가

#### 같은 종류의 버프로 그룹화한다면?

가장 높은 버프만 적용할 것인가, 모두 합산할 것인가?

#### 곱셈 vs 덧셈 적용 순서는?

%기반 버프가 적용되는 기준 값(기본 공격력? 무기 포함?)은 무엇인가?

# 디버프 복합 계산

#### 상황 설정

- 내 캐릭터 : 마방 0, HP 1000
- 0.5초 간격으로 티모 버섯 3개를 연속 밟음
- 버섯 효과 : 초당 50 마법 피해 x 4초
- 티모 아이템 : 리안드리의 고통 장착

#### 리안드리의 고통 효과

- 스킬 공격 시 현재 체력의 2% 추가 마법 피해 (3초에 걸쳐)
- 이속 감소 상태이면 추가 피해 2배 적용

초당 받는 총 피해량과 이동 속도 감소 상태는 어떻게 계산되어야 할까?

#### 계산

> 버섯 1개 기준 피해 계산 (밟는 순간 HP = 1000):
> 1. 버섯 기본 피해 : 초당 50 x 4초 = 총 200 피해 (4초에 걸쳐 분산)
> 2. 리안드리 추가 피해 (현재 체력의 2%. 3초에 걸쳐):
>    - 밟는 순간 현재 체력 기준 → 1000 x 2% = 20 추가 피해 (3초 분산)
>    - 버섯은 이속 감소 효과 포함 → 이속 감소 상태이므로 추가 피해 2배 적용 → 20 x 2 = 40 추가 피해
> 3. 버섯 1개당 총 피해 : 200 + 40 = 240
>    버섯 3개를 0.5초 간격으로 밟을 경우 :
>    - 각 버섯의 피해가 독립적으로 중첩 적용됨
>    - 단, 리안드리 피해는 밟는 시점의 현재 체력 기준으로 계산되므로, 두번째·세번째 버섯을 밟을 때는 이미 HP가 감소한 상태 → 추가 피해 수치도 줄어듦
>    - 이처럼 "현재 체력 기준" 피해는 매 적용 시점마다 기준값이 달라지므로, 중첩 계산 시 순서와 타이밍이 결과에 영향을 미침
>
> 핵심 설계 포인트 :
> - 동일 효과의 중첩 적용 여부 (버섯 3개가 각각 독립 스택인가?)
> - 리안드리 피해의 기준 시점(적용 시작 시 체력? 매 틱 체력?)
> - 이속 감소 판정 시점 (버섯 밟는 순간? 매 틱?)
>
> 이 세 가지를 정의하지 않으면 구현마다 결과가 달라진다.

# 버프와 디버프의 충돌

이동 속도를 낮추는 **Slow 디버프**가 걸린 상태에서, 이동 속도를 높이는 **Haste 버프**가 추가로 걸린다면?

#### Case A | 독립 유지

두 효과가 각각 별도 테이블에 독립적으로 존재하며, 매 틱마다 수치를 합산해 최종 값을 계산한다.
예 : Slow -30%, Haste +20% → 최종 이동 속도 = 100 X (1 - 0.10) = 90
한쪽이 먼저 만료되면 나머지 효과만 자동 반영된다.

#### Case B | 덮어쓰기

절댓값이 더 큰 효과만 활성화되고, 약한 효과는 무시 또는 제거된다.
예 : Slow -30%, Haste +20% → Slow 우선 적용, 최종 이동 속도 = 70
강한 효과 만료 후 약한 효과의 부활 여부도 반드시 정의해야 한다.

#### Case C | 그룹 분리

버프/디버프를 별도 그룹으로 분리해 각각 합산한 뒤, 두 결과를 곱해 최종 값을 계산한다.
예 : 버프 +20%, 디버프 -30% → 100 x 1.20 x 0.70 = 84
그룹 간 최종 합산 방식(덧셈 vs 곱셈)을 설계 초기에 명확히 정의해야 한다.

# 버프 설계 시 체크사항

#### 별도 테이블로 관리

모든 버프·디버프를 별도 테이블로 정의하고, 캐릭터에 적용 중인 효과는 (ID + 남은 시간) 리스트로 관리한다.

테이블 필수 항목 : 고유 ID / 효과 종류 / 수치 / 지속시간 / 출처 그룹 / 해제 조건 이 구조를 갖추면 새 버프 / 디버프 추가 시 테이블에 행 하나만 추가하면 되므로, 코드 수정 없이 확장이 가능하다.

#### 중복 수신 처리 규칙

같은 버프를 두 번 받을 때 버프별로 처리 방식을 정의해야 한다.

- 시간 갱신 (Refresh) - 수치 유지, 남은 시간만 초기화
- 누적 (Stack) - 수치 또는 시간 합산. Max Stack 상한 필수
- 무시 (Ignore) - 중복 적용 차단. 무적 등 고정 효과에 적합

버프 테이블에 처리 규칙과 최대 중복 횟수를 함께 정의해야 한다.

#### 기준 값과 적용 순서 결정

기준 값(base Value) 정의 : +10% 공격력 버프의 기준을 무엇으로 삼느냐에 따라 결과가 달라진다.

- 맨손 기준 : 100 x 1.10 + 50 + 20 = 180
- 무기 장착 후 기준 : (100 + 50) x 1.10 + 20 = 185
- 오라 적용 후 기준 : (100 + 50 + 20) x 1.10 = 187

적용 순서 (Order of Operations) : 덧셈·곱셈 버프가 혼재할 경우 순서에 따라 결과가 달라진다. 덧셈 먼저 / 곱셈 먼저 / 곱셈 중첩(1.10 x 1.20 = 1.32) 중 하나를 게임 전체에서 일관되게 정의하고 문서화한다.

#### 버프 출처 구분

출처마다 중복 적용 규칙과 우선순위가 달라지므로, 반드시 출처별로 분류해 관리해야 한다.

- 스킬 - 직접 발동. 중복 적용 여부 별도 정의 필요
- 아이템(물약·스크롤) - 동일 계열 중복 허용 여부 및 상위 덮어쓰기 결정
- 이벤트 / PC방 - 자동 부여. 일반 버프와 별도 그룹 관리
- 퀘스트 보상 - 중복 수령 방지 로직 필요
- 종족 / 길드 보상 - 패시브 상시 적용. 탈퇴 시 즉시 해제 여부 정의

#### 그룹화와 덮어쓰기

버프를 출처·효과 유형별로 그룹화하고, 버프 테이블에 그룹 ID와 우선순위(Priority)를 포함해야 한다.

- Lv1 방패(+10) 적용 중 → Lv3 방패(+20) 수신 : 상위 버프로 즉시 교체. 최종 +20 유지
- Lv3 방패(+20) 적용 중 → Lv1 방패(+10) 수신 : 하위 버프 무시. 최종 +20 유지

추가 정의 필요 사항 :
- 그룹이 다른 버프(스킬 vs 아이템)는 독립 적용 or 합산 여부
- 덮어쓰기 시 기존 지속 시간 승계 or 초기화 여부
- 동일 우선순위 충돌 시 나중 버프 우선 or 먼저 받은 버프 유지 여부

#### 해제 후 능력치 복원

기본 HP 200 + HP +100버프 → 최대 HP 300. 피격 후 현재 HP 99. 버프 해제 시 :

- 방식 A | 비율 유지 : 99/300 x 200 = 66 → HP 66(자연스럽지만 계산 복잡)
- 방식 B | 차감 복원 : 99 - 100 = -1 → HP 0 이하. 사망 처리 or HP 1 고정 예외 처리 필수
- 방식 C | 현재 HP 유지 : HP 99 유지. 최대 HP만 200 복원 (구현 단순)

세 방식 중 정답은 없다. 게임 전체에서 하나를 일관되게 적용하고, HP·마나·스테미나 등 모든 임시 자원 버프에 동일한 로직을 적용한다.

# 디버프 설계 시 체크사항

#### 별도 테이블로 전체 목록 관리

모든 디버프를 테이블로 정의하고, 캐릭터에 적용 중인 디버프는 **(ID + 남은 시간)**리스트로 별도 관리한다.

테이블 필수 항목 : **고유 ID / 종류 / 수치 / 기본 지속 시간 / 해제 조건 / 중복 처리 규칙 / Max Stack**

주요 디버프 유형 :
- Stun - 이동·공격·스킬 불가
- Blind - 원거리 명중률 0 또는 대폭 감소
- Silence - 스킬 불가. 기본 공격 허용
- Sleep - 모든 행동 불가. 피격 시 즉시 해제
- Slow - 이동 속도 % 감소. 중첩 여부 별도 정의
- Curse - 능력치 감소. 지속 시간 동안 유지
- Knockback - 강제 이동. 지속 시간 없이 즉시 처리

#### 중복 적용 처리 및 횟수 제한

디버프별로 중복 적용 방식을 명확히 정의한다.

- 시간 갱신 (Refresh) - 남은 시간 초기화. Stun 등 강한 제어기에 적합
- 누적 (Stack) - 수치 또는 시간 합산. Max Stack 상한 필수. 예 Slow -20% x 2 = -40%
- 무시 (Ignore) - 중복 차단. Sleep 등 피격 해제형에 적합

Max Stack 미설정 시 리스트가 무한 증가해 성능 문제가 생길 수 있다.

#### 지속 시간 및 해제 조건

지속 시간은 스킬 테이블에서 관리한다. 같은 Stun도 스킬마다 시간이 다를 수 있기 때문이다.

해제 조건 유형 :
**시간 경과 / 피격 / 해제 마법·아이템 / 특정 행동 / 사망 시 초기화**. 복수 조건인 경우 OR(하나만 만족) vs AND(모두 만족) 처리 방식도 함께 정의한다.

*(이미지 생략: 상태 이상/버프 설계 참고 이미지)*
