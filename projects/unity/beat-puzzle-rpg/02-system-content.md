# Beat Puzzle RPG (가제) 시스템/컨텐츠 기획서

- **작성일**: 2026-08-11
- **버전**: v1.1.0
- **연관 문서**: [01-concept.md](./01-concept.md), [references.md](./references.md)

## 개요

1차 컨셉의 핵심 재미("정확한 타이밍 배치의 손맛 + 즉각적인 캐릭터 성장 + 전투 연출의 즉각적 확신")와 핵심 루프(인게임: 배치→판정→콤보/피버→전투 연출→등급/성장, 아웃게임: 선택→플레이→결과→강화→재도전)를 아래 10개 시스템으로 구현한다. 시스템 디자인의 4항목(구조·규칙·시퀀스·UI) 기준으로 각 시스템을 정리했다.

## 시스템 상세

우선순위 "상" 시스템은 빈칸 없이 채웠다. 우선순위 "중"은 흐름까지, "하"(MVP 이후로 미루는 시스템)는 개요 수준만 채우고 나머지는 `(추후 채움)`으로 남겼다. 실제 수치(ms, 배율, 스탯값)는 여기 적지 않고 `03-detail/`로 위임한다.

### 퍼즐 배치/판정 시스템

- **목적**: "비트에 맞춰 퍼즐 피스를 배치"하는 단일 행위가 곧 판정이 되는 핵심 재미를 구현한다. QQQbeats!!!처럼 퍼즐 판정과 리듬 판정을 분리하지 않는다([references.md](./references.md) 참고).
- **구조**: `Board`(칸 배열 상태) / `Piece`(현재 조작 중인 피스: 모양·색·위치) / `PieceQueue`(피스 랜덤화 시스템이 공급하는 다음 피스 목록) / `JudgmentWindow`(보정된 판정 시각 기준 허용 오차). `Piece`가 `Board`에 배치되는 시각을 `JudgmentWindow`와 비교해 판정 등급을 산출한다.
- **규칙**:
  - 판정 등급은 3단계로 시작한다: Perfect / Good / Miss(StepMania·osu!mania 사례 참고, 세부 ms 값은 `03-detail/balance.md`에서 확정).
  - 피스 공급 순서는 피스 랜덤화 시스템이 결정한다(이 시스템은 소비만 한다).
  - 라인/패턴이 완성되면 즉시 클리어되고 점수·콤보가 갱신된다.
- **흐름**:
1. `PieceQueue`에서 다음 피스를 `Board`에 스폰
2. 유저 입력(회전/이동)을 매 프레임 반영
3. 배치 확정 입력 시각을 `JudgmentWindow`와 비교해 판정 등급 산출
4. 라인/패턴 완성 여부 확인 → 완성 시 클리어 처리(점수·콤보 갱신)
5. 1로 복귀
- **상태**: `대기`(피스 스폰 전) → `조작 중`(유저 입력 반영) → `배치 확정`(Entry: 판정 계산 / Do: 이펙트 재생 / Exit: 클리어 체크) → `대기`로 복귀. 스테이지 종료 조건 충족 시 `종료` 상태로 전이.
- **예외 처리**:
  - 판정 대상 프레임에 여러 입력이 동시에 들어오면 마지막 확정 입력만 유효 처리한다.
  - 일시정지 중에는 `JudgmentWindow` 타이머를 정지시켜 재개 후 오판정이 나지 않도록 한다.
- **UI 개요**: 메인 플레이 화면(보드 + 다음 피스 미리보기 + 판정 이펙트), 일시정지 화면.

### 피스 랜덤화 시스템

- **목적**: 특정 피스가 몰리거나 오래 안 나오는 상황을 방지해, 퍼즐 난이도가 랜덤성 때문에 불공정해지지 않게 한다.
- **구조**: `PieceBag`(현재 bag에 남은 피스 목록) / `PieceQueue`(다음 노출될 피스 순서, 퍼즐 배치/판정 시스템에 공급).
- **규칙**:
  - 7종 피스를 한 bag에 전부 담고 무작위로 섞어 하나씩 꺼낸다(테트리스 표준 7-bag, [references.md](./references.md) 참고).
  - bag이 비면 다시 7종을 채워 섞는다 — 같은 피스가 12개 이상 연속으로 안 나오는 상황을 원천 차단.
  - `PieceQueue`는 항상 다음 N개(미리보기 개수는 `03-detail/ui.md`에서 확정)를 미리 노출한다.
- **흐름**:
1. `PieceBag`이 비어있으면 7종을 채우고 셔플
2. bag에서 피스 하나를 꺼내 `PieceQueue` 끝에 추가
3. `PieceQueue`에서 다음 피스를 퍼즐 배치/판정 시스템의 `Board`로 스폰
4. 1로 복귀
- **상태**: 해당 없음(순수 데이터 공급 로직, 상태 다이어그램보다 흐름이 적합).
- **예외 처리**: 해당 없음 — 7-bag 규칙 자체가 편중 문제를 방지하는 설계라 별도 예외 분기가 없다.
- **UI 개요**: 별도 화면 없음(메인 플레이 화면의 다음 피스 미리보기에 결과만 노출).

### 콤보/피버 시스템

- **목적**: 판정 정확도를 콤보 배율로 전환하고, 이를 다시 성장 재화 획득량에 연결해 "정확할수록 크게 보상받는다"는 상벌 구조를 만든다.
- **구조**: `ComboCounter`(연속 성공 판정 수) / `ComboMultiplier`(콤보 구간별 배율 테이블 참조) / `FeverState`(피버 발동 여부·잔여 시간). `ComboCounter`가 일정 값에 도달하면 `FeverState`가 활성화된다.
- **규칙**:
  - 콤보 배율은 계단식으로 상승한다(구간·배율표는 `03-detail/balance.md`에서 확정, references.md의 "1x→2x→4x→8x" 계단식 사례 참고).
  - Miss 판정 시 `ComboCounter`는 0으로 초기화되고 `FeverState`는 즉시 해제된다.
  - 피버 상태 중에는 성장 재화 획득량에 추가 배율(예: x2)이 곱연산으로 적용되고, 전투 연출 시스템에 필살기 연출 트리거 이벤트를 보낸다.
- **흐름**:
1. 판정 등급 수신(Perfect/Good/Miss)
2. Miss면 콤보 초기화 + 피버 해제, 아니면 콤보 +1
3. 콤보 구간 갱신 → 배율 테이블 조회
4. 콤보가 피버 발동 기준 도달 시 `FeverState` 활성화(지속시간 타이머 시작) → 전투 연출 시스템에 이벤트 전달
5. 획득 점수 = 기본 점수 × 콤보 배율 × (피버 활성 시 피버 배율)
- **상태**: `평상`(Entry: 배율 1배) → `콤보 상승 중`(Do: 콤보 수 갱신) → `피버`(Entry: 추가 배율 적용 + 전투 연출 이벤트 발행 / Do: 잔여시간 감소 / Exit: 배율 해제 + 전투 연출 종료 이벤트 발행) → `평상`으로 복귀. Miss 발생 시 어느 상태에서든 즉시 `평상`으로 강제 전이.
- **예외 처리**: 피버 지속 중 스테이지가 종료되면 남은 피버 시간은 소멸시키고 정산에는 반영하지 않는다(확정). 잔여 시간을 재화로 환산하는 별도 규칙은 두지 않아 정산 로직을 단순하게 유지한다.
- **UI 개요**: 메인 플레이 화면 내 콤보 카운터·피버 게이지 표시(별도 화면 없음, 위치·연출은 `03-detail/ui.md`에서 구체화).

### 전투 연출 시스템

- **목적**: 퍼즐 판정 정확도(콤보/피버)를 캐릭터 전투 우위로 즉시 시각화해 "내가 잘하고 있다"는 확신을 실시간으로 체감시킨다(01-concept.md 핵심 재미·세계관 "전투의 의미" 참고).
- **구조**: `BattleStage`(캐릭터·전투 대상 개체와 현재 연출 상태를 담는 객체) / `BattleAnimationCue`(판정 등급·피버 발동 여부에 대응하는 연출 트리거 목록). 콤보/피버 시스템의 `FeverState` 변화 이벤트를 수신해 `BattleAnimationCue`가 대응 연출을 `BattleStage`에 재생 요청한다.
- **규칙**:
  - 평상시 판정(Perfect/Good)은 캐릭터의 약한 공격 모션으로, 피버 발동 시에는 강화된 필살기 모션으로 전환된다(01-concept.md 파생 컨텐츠 "전투 연출" 참고).
  - 연출은 퍼즐 보드 위/뒤에 오버레이되는 형태로만 재생하고 별도 컷씬으로 전환하지 않는다 — 재생 중에도 비트 판정 입력을 막지 않는다(01-concept.md 리스크 대응 방안 반영).
  - 연출 길이는 1~2박 이내로 제한해 판정 흐름을 끊지 않는다.
- **흐름**:
1. 콤보/피버 시스템으로부터 판정 등급 또는 `FeverState` 변화 이벤트 수신
2. 이벤트에 대응하는 `BattleAnimationCue` 조회
3. `BattleStage`에 오버레이 연출 재생 요청(퍼즐 입력 논블로킹)
4. 연출 종료 후 평상 상태로 복귀, 1로 대기
- **상태**: `평상 전투 모션`(Entry: 기본 대기 모션) → `약한 공격 연출`(Perfect/Good 판정 시 짧게 재생 후 평상으로 복귀) / `평상 전투 모션` → `필살기 연출`(Entry: 피버 발동 시 강화 모션 재생 / Do: 잔여 피버 시간 동안 유지 / Exit: 피버 종료 시 평상으로 복귀).
- **예외 처리**: 필살기 연출 재생 중 Miss로 피버가 강제 해제되면, 재생 중인 연출을 즉시 끊지 않고 자연스러운 지점까지만 재생한 뒤 평상으로 복귀한다(끊김으로 인한 위화감 방지).
- **UI 개요**: 메인 플레이 화면 내 캐릭터·전투 연출 레이어(별도 화면 없음, 실제 이펙트·컬러·타이밍은 `03-detail/design.md`에서 구체화).

### 캐릭터 성장 시스템

- **목적**: 스테이지에서 획득한 성장 재화를 캐릭터 스탯으로 전환하고, 그 성장이 실제로 다음 스테이지의 난이도 대응력에 반영되게 한다(Theatrhythm Final Fantasy 반면교사 — 치장으로만 끝나지 않게).
- **구조**: `GrowthCurrency`(라운드 종료 시 점수→환산된 재화) / `CharacterStat`(정확도·콤보 유지력·속도 대응력 3종). 퍼즐앤드래곤 사례처럼 "무엇을 성장시키면 무엇이 쉬워지는가"를 1:1에 가깝게 연결한다([references.md](./references.md) 참고). 스킬·장비는 별도 시스템(스킬/장비 시스템)이 담당한다.
- **규칙** (대응 관계 초안, 세부 수치는 `03-detail/balance.md`·`03-detail/character.md`에서 확정):
  - **정확도 스탯** → `퍼즐 배치/판정 시스템`의 `JudgmentWindow` 폭을 소폭 확장(Perfect 판정을 더 관대하게).
  - **콤보 유지력 스탯** → `콤보/피버 시스템`에서 Miss 시에도 콤보가 완전히 0이 되지 않고 일부만 감쇠.
  - **속도 대응력 스탯** → 고BPM 스테이지에서 피스 표시/예고 시간을 소폭 늘림.
  - 라운드 종료 시 점수→재화 환산 공식은 `03-detail/balance.md`에서 정의.
- **흐름**:
1. 스테이지 종료 → 최종 점수 확정
2. 점수를 `GrowthCurrency`로 환산
3. 라운드 종료 시 정해진 배분 규칙에 따라 재화가 스탯에 자동 분배된다(확정) — 별도 분배 선택 화면 없이 정산 화면에서 결과만 보여줘, "정확한 타이밍 → 즉각적인 성장"이라는 핵심 재미의 체감을 끊지 않는다.
4. 갱신된 `CharacterStat`이 다음 스테이지 진입 시 판정·콤보 시스템에 파라미터로 반영
- **상태**: 해당 없음(라운드 종료 후 1회성 처리, 상세 성장 UI 흐름은 `03-detail/ui.md`).
- **예외 처리**: MVP 범위(스테이지 10개 내외)에서는 별도 스탯 상한을 두지 않는다(확정) — 스테이지 수 자체가 유한해 성장치가 자연스럽게 상한선을 갖는다. 스테이지 수가 크게 늘어나는 확장 단계에서 재검토한다.
- **UI 개요**: 라운드 종료 정산 화면, 캐릭터 성장/스탯 화면.

### 스킬/장비 시스템

### 난이도 진행 시스템

- **목적**: 스테이지가 진행될수록 BPM과 패턴 복잡도를 단계적으로 올려 도전 곡선을 만든다.

### 스테이지 결과(등급) 시스템

- **목적**: Perfect/Good/Miss 판정 비율로 스테이지 클리어 등급을 산출해, 이미 클리어한 스테이지도 더 높은 등급을 위해 재도전하게 유도한다(01-concept.md 파생 컨텐츠·아웃게임 루프 참고).
- **구조**: `JudgmentTally`(스테이지 동안 누적된 Perfect/Good/Miss 횟수) / `StageGrade`(등급 산출 결과, 예: 별점).
- **규칙**: 스테이지 종료 시 `JudgmentTally`의 비율로 `StageGrade`를 산출한다(등급 구간 수치는 `03-detail/balance.md`에서 확정). 재도전 시 더 높은 등급만 저장하고, 낮은 재도전 결과로 기존 등급을 덮어쓰지 않는다.
- **흐름**:
1. 스테이지 진행 중 매 판정마다 `JudgmentTally` 갱신
2. 스테이지 종료 시 비율 계산 → `StageGrade` 산출
3. 기존 저장된 등급보다 높으면 갱신, 아니면 유지
4. 결과 화면에 `StageGrade` 표시
- **상태**: 해당 없음(스테이지 종료 시 1회성 처리).
- **예외 처리**: `(추후 채움)`

### 오디오 싱크/캘리브레이션 시스템

- **목적**: Android 기기의 오디오 출력 지연(기기별 편차 약 10~200ms)과 터치 입력 지연을 보정해, 모든 기기에서 동일한 체감 판정 기준을 제공한다.
- **구조**: `AudioClock`(DSP 기준 시각을 관리하는 객체, `AudioSettings.dspTime` 참조) / `CalibrationProfile`(기기·계정별 보정 오프셋 값을 담는 객체). 판정 시스템은 `CalibrationProfile`이 제공하는 보정된 시각만 참조하고 원본 dspTime을 직접 다루지 않는다(캡슐화).
- **규칙**:
  - 곡 재생은 `AudioSource.PlayScheduled`로 특정 DSP 시각에 예약한다.
  - 캘리브레이션 단계에서 유저가 일정 박자(예: 8박)를 탭하면, 각 탭 시각과 목표 박자 시각의 차이를 평균 내어 오프셋으로 저장한다.
  - 오프셋은 기기(또는 계정)별로 로컬에 저장하고, 설정 메뉴에서 재측정 가능하게 한다.
- **흐름**:
1. 최초 실행 시 캘리브레이션 화면 진입
2. 메트로놈 박자 재생 + 유저 탭 입력 8회 수집
3. 탭 시각과 박자 시각의 평균 오차 계산 → 오프셋 저장
4. 이후 모든 스테이지의 판정 시각에 오프셋 적용
- **상태**: 해당 없음(1회성 시퀀스 처리이며 상태 다이어그램보다 시퀀스 다이어그램이 적합).
- **예외 처리**:
  - 유저가 8회 탭 중 절반 이상을 놓치면 캘리브레이션을 재시도하도록 안내한다.
  - 오차가 비정상적으로 크면(예: ±300ms 이상) 오프셋 0(기본값)으로 되돌리고 재시도를 권한다. 정확한 임계값은 `(추후 채움)` — 플레이테스트로 확정.
- **UI 개요**: 캘리브레이션 화면(최초 1회 + 설정에서 재실행).

## 컨텐츠 순환 구조

- **핵심 가치**: 유저는 "정확한 타이밍으로 쌓은 콤보가 곧바로 눈에 보이는 성장으로 이어지는 것"을 가장 중요하게 여긴다(01-concept.md 핵심 재미·핵심 경험과 일치).
- **획득 → 소비 흐름**:
1. 스테이지 플레이로 점수·콤보 획득 (콤보/피버 시스템이 배율로 증폭)
2. 점수를 성장 재화로 환산
3. 재화를 스탯 강화에 소비
4. 강화된 캐릭터로 더 어려운 다음 스테이지에 도전 → 1로 복귀(더 높은 재화 획득 기회)

파생 콘텐츠(피버 타임)는 이 순환에 "일시적 배율 부스트"로 개입해 획득 속도에 변주를 준다. 전투 연출 시스템은 이 피버 구간을 시각적으로 부각시키는 연출 레이어로 개입하고, 스테이지 결과(등급) 시스템은 한 바퀴(스테이지 클리어) 뒤 더 높은 등급을 노리는 재도전 동기를 부여하는 리텐션 장치로 작동한다(01-concept.md 아웃게임 루프 참고). 버려지는 콘텐츠가 없도록, MVP 범위(단일 캐릭터·스탯 3종)에서는 모든 재화가 캐릭터 성장 한 곳으로만 소비되게 해 소비처 분산에 따른 잔여 재화 누적을 방지한다(스킬/장비는 MVP 이후 도입되는 별도 소비처).

## 플레이어 진행 흐름

레벨 구간 3단계(온보딩→성장→마스터) 원칙을 스테이지 단위로 적용한다.

1. **최초 실행(온보딩)**: 오디오 싱크/캘리브레이션 → 튜토리얼 스테이지(낮은 BPM·단순 패턴으로 핵심 루프를 자연스럽게 학습, 슈퍼 마리오 1-1식 무설명 학습 원칙 참고)
2. **초반 스테이지(온보딩~성장 초입)**: 낮은 BPM·단순 패턴으로 진행하며 첫 성장 재화 획득·분배를 체험
3. **중반 스테이지(성장)**: BPM·패턴 복잡도 상승, 스탯 성장이 실제 난이도 대응에 필요해짐(성장 미체감 시 리스크 — 01-concept.md 참고)
4. **후반 스테이지(MVP 마지막 구간, 마스터)**: 스탯 성장 없이는 클리어가 빠듯한 난이도로 "성장의 필요성"을 체감시킴
5. **전 스테이지 클리어 후(리텐션)**: 스테이지 결과(등급) 시스템을 통해 더 높은 등급을 노리는 재도전 루프로 전환(01-concept.md 아웃게임 루프 참고)
